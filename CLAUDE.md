# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

MovieTagger — a native macOS 13+ SwiftUI app (Swift 5.9) that tags MP4 files with TMDb movie metadata by writing MP4 atoms in place (no re-encode) and optionally renaming files. **Zero third-party dependencies is a deliberate principle** — everything is built on Apple frameworks (SwiftUI, AVFoundation, CryptoKit, Security). Don't introduce packages.

## Build

The Xcode project is **generated by XcodeGen** — `project.yml` is the source of truth.

```bash
# NEVER edit MovieTagger.xcodeproj/project.pbxproj directly.
# After changing project.yml or adding/removing source files:
xcodegen generate

# Build (Debug)
xcodebuild -project MovieTagger.xcodeproj -scheme MovieTagger -configuration Debug \
  -derivedDataPath build/DerivedData build
```

There is **no test target**. Verification is done by building plus manual/scripted checks (e.g. piping the live GitHub API response through a scratch Swift script to test decoders).

- Version numbers live **only** in `project.yml` (`MARKETING_VERSION`, `CURRENT_PROJECT_VERSION`); `Info.plist` references `$(MARKETING_VERSION)`/`$(CURRENT_PROJECT_VERSION)`. Bump both when cutting a release.
- `build/` is gitignored; all archives/artifacts go there.
- App icon is generated: `/opt/homebrew/bin/python3.11 create_icon.py` (needs Pillow + numpy; the default `python3` doesn't have them). It writes all sizes into `Assets.xcassets/AppIcon.appiconset/` with unchanged filenames.

## Release (signed + notarized)

Use the `/release-build` skill (`.claude/skills/release-build/SKILL.md`) — it encodes the full flow and its gotchas. Summary: bump versions in `project.yml` → `xcodegen generate` → `xcodebuild archive` (Release config is wired for **manual Developer ID signing, Team 9R236BB67S, Hardened Runtime**) → package with `ditto -c -k --keepParent` (never plain `zip` — it corrupts bundles) → `xcrun notarytool submit --wait --keychain-profile "MovieTagger"` → `xcrun stapler staple` → re-zip → verify with `spctl -a -t exec` → tag `vX.Y` → `gh release create` with the zip attached.

- The release asset **must** be named `MovieTagger-<version>.zip` and the tag `v<version>` — the in-app auto-updater matches assets by the `MovieTagger*.zip` pattern and parses the tag numerically.
- Notarization 403 "required agreement missing" means a pending Apple Developer agreement — only the account holder can accept it; acceptance takes minutes to propagate.
- A stray `.app` committed into `MovieTagger/` will be bundled into `Contents/Resources/` and fail notarization; `project.yml` excludes `**/*.app` as a guard.

## Architecture

Single-window wizard app. `AppState` (in `MovieTaggerApp.swift`) is the app-wide `ObservableObject` that owns:

- **screen routing** — `currentScreen` enum; `ContentView` switches over it (fileSelection → movieSearch → reviewEdit → progress) and gates the whole app on `apiKey.isEmpty`
- **the edit session** — `movieEditModel: MovieEditModel` plus `selectedFileURL`, `detectedResolution`, and search state (`searchQuery`, `searchResults`, `hasSearched` — kept here so results survive Back navigation)
- **file selection** — `selectFile(_:)`/`chooseFileViaPanel()` including AVAsset validation (unreadable files are rejected at selection time)

The scene is `Window` (not `WindowGroup`) on purpose — a second window sharing `AppState` was a bug. The `File > Open` and `Check for Updates` menu commands are small `View` structs holding `@Environment(\.openWindow)`.

Services (all in `MovieTagger/Services/`):

- **`TMDbClient`** — actor; TMDb v3 API with `api_key` query param. 401 maps to a user-facing "Invalid API key" message; `AppState.showError` flags auth failures so the error alert can offer "Open Settings".
- **`MetadataWriter`** — writes MP4 atoms directly via `FileHandle`, **in place and irreversibly**. This is the highest-risk code in the repo; the UI requires explicit confirmation before invoking it.
- **`FilenameFormatter`** — token substitution + collision resolution. Two invariants: `formatIfValid` returns `nil` for patterns that produce an empty/dot-leading stem (callers must then *skip* renaming, never produce a dotfile), and `resolveCollision(excluding:)` must exclude the source file so a file already named per the pattern doesn't self-collide into "Name (1)". **The rename preview in ReviewEditView must run the identical formatter+collision logic as the actual write** — they may never disagree.
- **`KeychainHelper`** — despite the name, not the system Keychain: an encrypted file in Application Support (ChaCha20-Poly1305, key derived from the hardware UUID, so the file is machine-bound).
- **`UpdateChecker`** — `UpdateManager` (@MainActor) drives auto-update from this repo's public GitHub releases. Security gate: the downloaded bundle must pass `SecStaticCode` validation against a requirement pinned to the team ID *before* install; quarantine is stripped only after that check; downgrades are never offered. **`NSApp.terminate` is silently refused while a sheet or confirmationDialog is presented** (reproduced; alerts don't block) — the updater dismisses its sheet first and falls back to `exit(0)`. The old bundle must stay on disk until the process exits; the relaunch helper removes it afterwards.

  End-to-end test of the update flow (DEBUG builds only): launch the Debug binary *directly* with `MOVIETAGGER_FORCE_UPDATE=1 MOVIETAGGER_AUTO_ACCEPT_UPDATE=1` (force also bypasses the daily throttle; `open` can't pass env). It downloads the latest release, verifies, installs over the Debug bundle, self-terminates, and relaunches; milestones land in `$TMPDIR/movietagger-updater.log` and the unified log. Afterwards `rm -rf` the Debug products bundle — it's now the read-only release bundle and the next build will fail to overwrite it.

## Shell gotchas in Claude Code's Bash tool

- Commands run through **zsh**, where `log` is a **builtin** — `log show …` silently prints "too many arguments" and returns nothing. Always call **`/usr/bin/log`** for the unified log.
- The `osxkeychain` git credential helper can hang on an invisible dialog; push with `git -c credential.helper= -c credential.helper='!gh auth git-credential' push …`.

## Session-state invariants (bugs have hidden here)

- `movieEditModel` is **file-specific**: selecting a different file must clear the session (`selectFile` does this); Back + re-selecting the *same* movie for the *same* file reuses the model so edits survive.
- Async fetches that populate a model (posters) must write to the **captured model instance**, never through `appState.movieEditModel` at completion time — a slow response must not contaminate a newer session. Guard user-facing error alerts with `appState.movieEditModel === model`.
- Slow search responses are dropped unless the query still matches; a details load never navigates if the user already left the screen.
- All `@Published`/`@State` mutations happen on the MainActor — async work hops back via `MainActor.run` (or the method is `@MainActor`). This convention is followed everywhere; don't add the one exception.

## macOS 13 compatibility traps (deployment target is 13.0)

- No macOS-14-only API outside `#available` branches: no `.onKeyPress`, no `defaultFocus`, no two-parameter `onChange`.
- `NSApp.sendAction(Selector(("showSettingsWindow:")))` works on 13 but is **blocked by AppKit on 14+**; `SettingsLink` works on 14+ but **cannot be used inside alert actions** — for alerts use the `@Environment(\.openSettings)` action inside an `@available(macOS 14, *)` helper view, with the selector as the 13-only fallback (see `OpenSettingsAlertButton` in `ContentView.swift`).
- The old `showPreferencesWindow:` selector silently no-ops on 13+ — never reintroduce it.
